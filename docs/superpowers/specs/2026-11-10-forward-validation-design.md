# 새 후보 전진 검증 설계 (월 단위 후보 2개, 앞으로 쌓이는 구간으로 판정)

작성일 2026-11-10 · 초안 · 설계 문서 먼저, 구현은 승인 뒤. 앱 코드는 바꾸지 않는다.

**이 문서와 이 문서로 만드는 모든 결과는 투자 권유가 아니며, 그 결과만으로 실계좌 규칙을 바꾸면 안 된다.**

## 1. 목적과 사용자 결정

지금까지의 검증(PR #30~#32)은 현재 스윙 규칙이 비용 뒤 기대값이 0 이하이고, 개선 후보 F1·E3·S4가 검증 기간에서 불합격했음을 보였다. 2026-11-10 독립 검토는 그 결론의 방향은 타당하나 다음을 지적했다: 세 후보 모두 검증 기간을 본 뒤 고른 것(사전 노출)이고, 2022~2026 구간은 두 번 쓰였으며, 검정력이 낮고(연 20~30%p 효과만 검출), 생존편향과 분할 처리의 미래 정보가 남아 있다.

이번 단계는 문헌으로만 고른 새 후보 2개를 **아무도 미리 볼 수 없는 자료(앞으로 쌓이는 구간)** 로 한 번 판정하는 장치를 만든다.

| 결정(2026-11-10, 사용자) | 내용 |
|---|---|
| 판정 자료 | 앞으로 쌓이는 구간만. 규칙·판정일을 먼저 잠그고(사전 등록) 그 뒤 자료로 한 번 판정 |
| 과거 자료의 용도 | 세부 값 정하기 2014-08~2021 / 예행연습 2022~2026(이미 본 기간) / 필요 기간 측정 2014-08~2026 전체 |
| 접근 | C: 월 1회 스냅샷 + 판정일에 한 번 계산 |
| 후보 | ① 복권형 종목 회피 ② 지수 이동평균 게이트. (③ 산업 상대 반전은 "뉴스 없음" 판별 자료가 없어 제외, ④ 모멘텀은 앞서 제외) |
| 판정 기준 | 후보마다 자기 주 지표로 판정. KODEX 200 대비는 참고로 항상 병기(이전의 "KODEX 200보다 나음"은 며칠 거래용 기준이라 합격 조건에서 내림) |
| 보유기간 | 제한 없음(근거 우선). 앱에 넣는 방식은 합격 뒤 별도 설계 |
| 생존편향 | 판정 구간은 시작일의 종목 목록을 고정. 학습·예행연습은 "같은 종목 풀 안의 상대 비교"로만 읽음 |
| 비용 | 연도별 세율표 + 비용 1배·1.5배·2배. 백테스트 도구에만 적용, 앱의 `SELL_TAX_RATE`는 그대로 |
| 월 스냅샷 실행 | GitHub 예약 실행. 자료는 **비공개 자료 저장소**에 저장(이 저장소는 공개라서) |
| 코드 범위 | 새 폴더 `backtest/forward/`만. `backend/`·`strategy.py`·프론트와 기존 `backtest/` 파일은 수정하지 않고 불러다 쓴다 |
| 문서·PR | 설계서 하나, 구현 계획과 PR은 둘(1단계: 엔진·보정·학습 실행 / 2단계: 잠금·스냅샷·판정) |

범위 밖: 앱·전략 변경, 후보 추가(잠근 뒤), 판정 결과를 본 뒤의 재조정, 실거래 연동, 화면·서버 API.

## 2. 조사로 확인한 사실 (2026-11-10)

| 항목 | 결과 |
|---|---|
| 일봉 과거 범위 | 네이버 차트 API는 `count`를 6000으로 줘도 3000개만 준다. 삼성전자·KODEX 200 모두 첫 날짜가 2014-08-18. 그래서 과거 구간의 실제 시작은 2014-08이다 |
| 상장폐지 종목 일봉 | 한진해운(`117930`, 2017년 상장폐지)의 일봉을 지금도 받을 수 있었다(2009-12-29~2017-03-06, 1,778개). 한 종목만 확인했다. 과거에 상장폐지된 종목의 **목록**을 얻는 방법은 확인 못 함 |
| KODEX 200 매도 세금 | 국내 주식형 ETF는 매도 시 증권거래세가 붙지 않는다(자산운용사·세무 안내 자료 기준, 법령 원문은 확인 못 함) |
| MAX 정의 | 문헌 표준(Bali·Cakici·Whitelaw 2011)은 "직전 한 달의 일간 수익률 최댓값". Goh & Kim(2024) 원문의 세부 변형과 IVOL 계산식은 확인 못 함 |
| 저장소 | `swprk47/Alpha_Stock`은 공개 저장소. `backtest/results/`·`backtest/cache/`는 커밋 제외 |
| GitHub 서버의 네이버 접속 | 확인 못 함. 2단계 첫 작업에서 시험한다(8절) |

## 3. 공통 계산 규칙

| 항목 | 값 |
|---|---|
| 종목 목록 | 기존 `fetch_listing`(코스피 시총 상위 150 + 코스닥 시총 상위 150 = 300). **판정 구간**은 잠금 시점에 받은 목록을 고정한다. 학습·예행연습은 실행 시점의 목록을 쓴다(생존편향 있음, 상대 비교 전용) |
| 달력 | KODEX 200(`069500`) 일봉의 거래일. 신호일 = 그달의 마지막 거래일. 교체일 = 다음 달 첫 거래일 |
| 체결 | 교체일 시가. 슬리피지 0.1%(매수·매도 각각) |
| 수수료 | `fees`의 요율(매수·매도 각각) |
| 매도세 | 체결일 기준 연도별 세율표(4절). KODEX 200에는 붙이지 않는다 |
| 비용 배수 | 수수료·세금·슬리피지 전체에 1배·1.5배·2배. 판정은 1배 기준 |
| 비중 | 주식 수를 내림하지 않는 비율 계산(소액 계좌에서 그대로 따라 할 수 없음, 한계에 기록) |
| 거래정지 | 교체일에 거래정지인 종목은 사고팔 수 없고 기존 비중을 그대로 둔다. 재개된 뒤 다음 교체일에 맞춘다 |
| 상장폐지 | 일봉이 끊긴 종목은 마지막 거래일 종가에 판 것으로 본다(낙관적일 수 있음, 한계에 기록) |
| 자료 이상 | 일간 수익률이 ±31%를 넘는 날이 있는 종목은 그달 신호 계산에서 뺀다(가격제한폭 ±30%를 넘는 값은 자료 오류나 분할 미반영으로 본다. 상장 첫 행과 거래정지 직후 행은 수익률이 없어 이 검사에 걸리지 않는다). 미래 봉을 쓰지 않는다 |
| 미래 정보 | 신호일 t의 선정은 t까지의 일봉만 쓴다. 기존 도구의 분할 감지(`vol_break`·`pre_split`, 이후 20봉 사용)는 쓰지 않는다. 월 단위 후보는 수익률만 쓰고 명목 가격 조건이 없어 필요하지 않다 |
| 재추출 | 20,000회, 시드 20261110. 한쪽 확률은 재추출 표본에서 직접 계산한다(`mean(표본 <= 0)`). `analysis.bootstrap.block_indices` 재사용 |

| 체결일 | 세율 |
|---|---|
| ~2019-05-29 | 0.30% |
| 2019-05-30~2020-12-31 | 0.25% |
| 2021-01-01~2022-12-31 | 0.23% |
| 2023 | 0.20% |
| 2024 | 0.18% |
| 2025 | 0.15% |
| 2026~ | 0.20% |

2차 자료(기재부 발표·언론·예탁결제원 설명) 기준이며 법령 원문은 확인 못 했다. 2027년 이후는 마지막으로 아는 세율을 쓴다. **잠근 뒤 허용되는 유일한 변경은 법 개정에 따른 이 표의 미래 연도 추가**이고, 바꾸면 잠금 기록에 날짜와 근거를 남긴다.

## 5. 후보 2개 사전 등록 (잠근 뒤 변경·추가 금지)

두 후보는 코드의 등록표에 아래 그대로 넣고, 설계서와 어긋나면 테스트가 실패한다.

### 5.1 후보 ① 복권형 종목 회피

| 항목 | 정의 |
|---|---|
| 대상 | 종목 목록 중 신호일 t에 거래정지가 아니고, 그달에 거래정지가 아닌 거래일이 15일 이상이며, 자료 이상(3절)이 없는 종목 |
| MAX | 그달 일간 수익률(종가 대 전 거래일 종가)의 최댓값 |
| IVOL | 그달 일간 수익률을 같은 날 KODEX 200 일간 수익률에 회귀한 잔차의 표준편차(문헌은 3요인 모형을 쓰기도 하나 이 자료로는 시장 1요인만 가능. 문헌과 다른 점으로 기록) |
| 합성 순위 | 대상 종목 안에서 MAX와 IVOL의 백분위 순위를 평균한다. 값이 클수록 복권형 |
| 제외 | 합성 순위 상위 20%에 들면 제외한다. 제외된 종목은 합성 순위가 상위 30% 밖으로 나온 달부터 다시 넣는다 |
| 보유 | 제외되지 않은 대상 종목을 같은 비중으로, 매달 교체일에 다시 맞춘다 |
| 비교 대상 | 대상 종목 전체를 같은 비중으로, 같은 날 같은 비용으로 다시 맞춘 것 |
| 주 지표 | 비용 뒤 월 수익률 차이(회피 − 전체)의 평균 |
| 참고 지표 | KODEX 200 대비 수익, 월 편도 회전율, 연도별 차이, 비용 배수별 차이, 제외 종목 수 |

20%는 문헌의 5분위 구분에 맞춘 값이다. 30%(복귀 완충)와 15일은 문헌 값이 아니라 이 설계에서 정한 값이다. 2014-08~2021 학습에서 고를 수 있는 값은 이 완충 폭 하나이고, 후보값은 {완충 없음(20%), 30%}로 제한한다(회전율과 비용 뒤 차이로 고른다).

### 5.2 후보 ② 지수 이동평균 게이트

| 항목 | 정의 |
|---|---|
| 신호 | 신호일 t의 KODEX 200 종가가 최근 10개 월말 종가(t 포함)의 평균보다 낮으면 다음 달은 현금, 아니면 KODEX 200 보유 |
| 체결 | 상태가 바뀐 달의 교체일 시가. 현금 수익은 0% |
| 자료 부족 | 월말 종가가 10개 미만이면 보유로 둔다 |
| 비교 대상 | KODEX 200 계속 보유 |
| 주 지표 | 최대 낙폭 차이(계속 보유의 최대 낙폭 − 게이트의 최대 낙폭). 일별 종가 기준 |
| 참고 지표 | 줄어든 수익(계속 보유 − 게이트의 연 수익), 변동성, 신호 전환 횟수, 큰 하락별 낙폭 |
| 큰 하락 | 계속 보유 기준으로 고점 대비 15% 이상 내려간 구간(고점부터 회복 또는 기간 끝까지)을 하나로 센다 |

10개월 하나만 쓴다. 다른 길이·다른 지표는 시험하지 않는다(격자 탐색 금지). 수익이 늘어난다는 주장은 하지 않는다.

### 5.3 근거 강도 (정직한 표기)

| 후보 | 근거 | 약점 |
|---|---|---|
| ① | 한국 2000~2020 고-MAX 분위가 월 -2.08%(동일가중, t=-5.01), 가치가중 -1.80%(t=-3.28) (Goh & Kim 2024). 미국·유럽에서도 보고 | **상위 300종목으로 한정한 값은 어느 출처에도 없다.** 효과가 소형주에 몰려 있으면 여기서 사라진다. 인용은 초록·부분 원문 수준 |
| ② | 해외에서 낙폭 감소가 반복 보고됨. 수익 증대는 뒷받침되지 않음 | 한국 직접 증거가 얇다. 거짓 신호(휩소)와 반등 놓침. 큰 하락 횟수가 적어 판정이 오래 걸린다 |

## 6. 진행 단계

**1단계 (PR 1): 엔진·보정·과거 실행**
1. 학습(2014-08~2021): 기준(전체 보유)과 ①의 완충 후보값 2개, ②를 돌린다. ①의 완충 폭을 고른다.
2. 예행연습(2022~실행일): 고른 규칙으로 한 번 돌린다. ①은 비용 뒤 차이가 0 이하이면, ②는 최대 낙폭이 줄지 않았으면 **잠그기 전에 그 후보를 뺀다**. 통과해도 합격이 아니며 보고서에 "이미 본 기간"이라고 적는다.
3. 필요 기간 측정(2014-08~실행일 전체): ①은 월 차이의 표준오차로, 가정한 효과 크기(연 1·2·3·5%p)마다 "유의해지는 데 필요한 개월 수"를 계산한다(정규 근사, 한쪽 2.5%, 검정력 80%). ②는 과거에 큰 하락이 몇 년에 한 번 있었는지를 센다.
4. 보고서를 사용자에게 보인다. **사용자가 판정일을 확정한다.** 필요 기간이 5년 이상이면 잠그기 전에 다시 정한다(기간을 정해 두고 "유망까지만 가능"이라고 미리 적거나, 그 후보를 접는다).

**2단계 (PR 2): 잠금·스냅샷·판정**
5. 잠금: 등록 파일을 만들고 사용자 승인 뒤 이 저장소에 커밋한다. 시작일 = 잠금 커밋 다음 달의 첫 거래일(첫 교체일).
6. 월 스냅샷(8절).
7. 중간 보고(6개월마다, 판정 없음).
8. 판정(판정일에 한 번).

## 7. 판정

후보 수 N = 2. 유의 기준 = 0.05 / N = **2.5%**(한쪽).

### 7.1 후보 ①

월 차이 계열을 3개월 묶음으로 재추출한다.

| 판정 | 조건 |
|---|---|
| 합격 | 차이 평균 > 0 이고 한쪽 확률 ≤ 2.5%. **그리고** 비용 2배에서도 차이 평균 > 0 |
| 불합격 | 차이 평균 ≤ 0, **또는** 95% 구간의 위쪽 끝이 연 1%p 미만 |
| 유망 | 그 밖 |

합격 조건을 먼저 본다. 합격이면 불합격 조건(구간 위쪽 끝이 연 1%p 미만)은 적용하지 않고, 보고서에 "유의하지만 효과가 작다"고 적는다.

### 7.2 후보 ②

일간 수익률 쌍(게이트, 계속 보유)을 63거래일 묶음으로 재추출해 최대 낙폭 차이의 95% 구간을 구한다.

| 판정 | 조건 |
|---|---|
| 판정 보류 | 판정 기간에 신호 전환이 0번이거나 큰 하락이 2번 미만 |
| 합격 | 큰 하락이 2번 이상이고, 각각에서 게이트의 낙폭이 작았고, 최대 낙폭 차이 > 0 이며 95% 구간이 0을 포함하지 않는다 |
| 불합격 | 큰 하락이 2번 이상인데 최대 낙폭 차이 ≤ 0 |
| 유망 | 그 밖 |

판정 보류이면 12개월 뒤 같은 규칙으로 다시 판정한다. 연장은 최대 2번이고, 그래도 보류이면 "시험되지 않음"으로 끝낸다.

### 7.3 공통

- 판정일은 하나다. 중간 보고(6개월마다)는 참고 수치만 내고 합격을 선언하지 않는다(여러 번 보고 좋을 때 멈추면 우연 합격이 는다).
- **조기 종료는 한 가지뿐이다:** 중간 보고에서 ①의 95% 구간 위쪽 끝이 연 1%p 미만이면 ①을 불합격으로 끝낸다. "차이 평균 ≤ 0"만으로는 조기 종료하지 않는다(몇 달치 잡음으로 후보를 버리지 않기 위해).
- 합격이어도 "앱 반영을 논의할 후보"일 뿐이다. 반영은 별도 설계와 사용자 승인이 필요하다. 유망은 다음 시험의 출발점이다.
- 불합격은 "효과가 없다"가 아니라 "이 기간·이 검정력에서 보이지 않았다"는 뜻이라고 보고서에 적는다.
- 연 1%p, 15%, 2번, 6개월, 12개월·2번 연장, 묶음 길이(3개월·63거래일)는 문헌 값이 아니라 이 설계에서 정한 값이다.

## 8. 잠금·월 스냅샷·자료 저장소

**등록 파일(이 저장소에 커밋):** `docs/superpowers/registrations/forward-registration.json`. 후보 등록표와 그 지문, 고른 완충 폭, 종목 목록 300개(코드·이름·시장), 잠금일·시작일·판정일, 세율표, 비용·재추출 설정, 코드 지문(`backtest/forward/*.py`와 불러 쓰는 `backtest/data.py`·`backtest/analysis/bootstrap.py`·`backend/market_data.py`·`backend/fees.py`·`backend/config.py`의 내용 해시), 학습·예행연습·필요 기간 요약, 커밋 해시. 선정 종목이나 일봉은 넣지 않는다.

**비공개 자료 저장소(사용자가 만든다):**
| 경로 | 내용 |
|---|---|
| `candles/{code}.csv` | 종목 300개와 KODEX 200의 일봉. 매달 같은 파일을 갱신한다(과거 상태는 커밋 기록에 남는다) |
| `picks/YYYY-MM.json` | 그달 신호일, ①의 대상·제외·보유 목록과 합성 순위, ②의 상태, 코드 지문 |
| `manifest.json` | 마지막 실행 시각, 채운 달 목록, 받지 못한 종목 |

**예약 워크플로(`.github/workflows/forward-snapshot.yml`, PR로 `main`에 넣는다):**
- 매달 초 1회 예약 실행 + 수동 실행 버튼. 접근 키는 저장소 비밀값으로 사용자가 등록한다(키 값은 문서·대화·코드에 적지 않는다).
- 하는 일: 자료 저장소를 받아 온다 → 일봉을 받는다 → 빠진 달을 포함해 선정을 계산한다 → 자료 저장소에 커밋한다. `main`에는 아무것도 올리지 않는다.
- 등록 파일의 코드 지문과 현재 코드가 다르면 스냅샷은 계속하되 `manifest.json`과 실행 기록에 경고를 남긴다(자료를 잃지 않는 것이 먼저다).
- 공개 저장소의 예약 실행은 60일 동안 저장소 활동이 없으면 꺼진다. 중간 보고 때 실행 기록을 확인한다.

**2단계 첫 작업:** 수동 실행으로 GitHub 서버에서 네이버 일봉을 받을 수 있는지 시험한다. 막히면 같은 명령을 PC 예약 작업으로 돌리고 자료 저장소에는 PC에서 올린다(대체 경로, 그때 사용자와 확정).

**실행 명령:** `python -m backtest.forward.run --stage train | rehearsal | power | lock | snapshot | interim | judge`
- `lock`: 학습·예행연습·필요 기간 결과가 있고 판정일이 주어져야 한다. 등록 파일이 이미 있으면 거부한다.
- `judge`: 등록 파일이 없으면, 판정일 전이면, 이미 판정 결과가 있으면, 코드·등록표 지문이 등록 파일과 다르면 거부한다. `--allow-rerun`으로 강제하면 보고서 맨 앞에 "재실행 또는 코드·규칙 변경(결과 신뢰도 하락)" 표시를 넣는다.
- `judge`는 일봉으로 전체를 다시 계산하고 `picks/`의 기록과 대조한다. 다른 달은 보고서에 표로 적는다(분할로 과거 가격이 바뀐 경우 등). 판정은 다시 계산한 값으로 한다.
- 이 장치는 실수로 판정을 여러 번 하는 것을 막고 기록을 남기는 용도이며, 일부러 우회하는 것까지 막지는 못한다.

## 10. 보고서와 한계

보고서의 첫 줄은 "이 보고서는 투자 권유가 아니며, 이 결과만으로 실계좌 규칙을 바꾸면 안 된다"이고, 한계를 결과보다 먼저 쓴다. 반드시 들어갈 한계:

- 학습·예행연습은 오늘의 종목 목록을 써서 생존편향이 있다. 상대 비교로만 읽고 절대 수익·KODEX 200 대비는 참고다.
- 오늘의 시총 상위 목록에는 과거의 고변동·급등 종목 중 크게 오른 것만 남아 있고, 그 종목들은 "전체 보유" 쪽에만 들어간다. 그래서 회피 − 전체 차이는 회피에 불리한 쪽으로 치우칠 수 있다. 상대 비교도 이 치우침에서 자유롭지 않으며, 학습의 완충 폭 선택과 예행연습의 탈락 표시를 읽을 때 감안해야 한다.
- 2022~2026 예행연습은 이미 본 기간이라 통과해도 증거가 아니다. 변동성 관련 요소는 이전 분석에서 이 기간에 이미 봤다.
- 월 관측이 적어 검정력이 낮다. 필요 기간 측정값과 가정한 효과 크기를 같이 적는다.
- 판정 기간의 시장 국면 하나가 결과를 좌우할 수 있다.
- "상위 300"은 코스피 150 + 코스닥 150이며 문헌의 표본과 다르다. ①의 상위 300 한정 근거는 문헌에 없다.
- IVOL은 시장 1요인 잔차로, 문헌의 정의와 다를 수 있다.
- 교체일 시가 체결·슬리피지 0.1% 가정은 낙관적일 수 있다. 같은 비중 300종목 보유는 소액 계좌에서 그대로 따라 할 수 없다(1주 단위, 소수점 거래 가능 종목 한정).
- 상장폐지 종목을 마지막 종가에 판 것으로 본다(정리매매 손실 미반영).
- 판정 기간이 길어질수록 고정한 300종목이 "지금의 상위 300"과 달라진다(의도한 대가).
- KODEX 200은 분배금이 빠진 가격 수익률이다.
- 개별 종목 수익률도 배당이 빠진 가격 수익률이다. 복권형 종목은 배당이 낮은 편이라 회피 쪽에 조금 불리하다.
- 확률과 구간은 재추출 근사다. 최대 낙폭의 구간은 특히 거칠다.
- 세율은 2차 자료 기준이고 법령 원문은 확인 못 했다.
- 한 달의 유효한 날은 종목과 KODEX 200 모두 수익률이 있는 날로 센다. 거래정지 하루는 이틀을 빼므로 설계서의 "거래정지가 아닌 날 15일"보다 조금 엄격하다.

## 11. 테스트 방침

- **등록 가드:** 등록표가 5절과 정확히 같다.
- **미래 정보:** 신호일 t 이후의 일봉을 바꿔도 t의 선정이 같다(①, ②, 자료 이상 표시 모두).
- **①:** 손으로 계산한 작은 일봉에서 MAX·IVOL·합성 순위가 일치. 상위 20% 제외, 30% 밖에서 복귀, 완충 없음 설정. 거래일 15일 미만·거래정지·자료 이상 종목 제외. 동률 처리(종목 목록 순서).
- **②:** 10개월 평균 위·아래 전환, 월말 종가 10개 미만이면 보유, 전환한 달만 체결 비용.
- **엔진:** 교체일 시가 체결, 같은 비중 재조정, 회전율 계산, 거래정지 종목 비중 유지, 일봉이 끊긴 종목 처리, 현금 구간 0%, 비교 대상이 같은 날 같은 비용을 낸다.
- **비용:** 체결일별 세율(경계일 2019-05-29/30, 연도 경계), ETF 무세, 배수 1·1.5·2.
- **통계:** 묶음 재추출 설정, 한쪽 확률이 `mean(표본 <= 0)`, 최대 낙폭·큰 하락 찾기(합성 계열), 낙폭 차이 구간.
- **필요 기간:** 표준오차와 효과 크기에서 개월 수가 식대로 나온다.
- **판정:** ①의 합격·유망·불합격 경계, 2.5% 기준, 비용 2배 조건, 구간 위쪽 끝 연 1%p 조건, 조기 종료 조건. ②의 보류·합격·불합격·유망, 큰 하락 2번 조건, 연장 횟수.
- **잠금:** 등록 파일 없이 판정 거부, 판정일 전 거부, 두 번째 판정 거부, 지문 불일치 거부, `--allow-rerun` 표시, 등록 파일이 있으면 `lock` 거부, 세율표 미래 연도 추가만 허용.
- **스냅샷:** 빠진 달 채우기, 같은 달 재실행 시 기록 불변, `picks` 대조에서 다른 달을 찾는다, 받지 못한 종목 기록. 네이버에 접속하지 않는다(가짜 함수 주입).
- **통합:** 합성 종목으로 train → rehearsal → power → lock → snapshot → judge가 끝까지 돌고, 보고서 첫 줄과 한계가 결과보다 앞에 온다.
- 기존 테스트는 그대로 통과해야 한다. 앱 코드 변경이 없어 프론트 문법검사는 해당 없음.
