# UI 개편 디자인 명세 (확정 시안 기준)

작성일 2026-10-26. 코드는 아직 바꾸지 않았다. 이 문서는 확정된 시안을 구현할 때 따를 규칙이다.
시안 원본은 claude.ai의 비공개 디자인 캔버스(PC 8장, 모바일 9장)에 있고 저장소에는 없다(열린 결정 1번).

## 1. 범위와 전제
- 모바일 우선, PC는 별도 레이아웃. 앱은 주로 폰에서 쓴다.
- 구조는 현재 그대로(단일 `frontend/index.html`, Tailwind CDN, 프레임워크 없음). 구조 변경은 `PROJECT_PLAN.md` D항에 따로 기록했다.
- 아이콘은 Lucide 원본 SVG를 인라인으로 쓴다(약 15~20개, stroke 1.75). 애니메이션 아이콘 선정은 이 명세 다음 단계.
- 이번에 하지 않는 것: 시장 브리핑·뉴스(뉴스 작업 때 함께), 좌측 아이콘 레일, 자산 추이 꺾은선(일별 자산 기록이 없어서 실제 데이터로 못 그림), 전략(`strategy.py`) 변경.

## 2. 레이아웃
**PC** (1280 기준): 헤더 64px + 본문 2열 `440px | 1fr`.
- 왼쪽: 독립된 글라스 카드(바깥 여백 16px, 안쪽 20px). 자산 요약 → 탭(스윙 추천 / 보유 종목) → 목록.
- 오른쪽 두 가지 모드. 종목 미선택이면 **요약**(내 계좌, 자산 구성, 추천 등급 분포, 보유 종목 손익, 추천 점수 순위), 종목을 고르면 **상세**(시세 차트, 핵심 수치 4칸, AI 진단, 매수 패널). 선택한 카드를 다시 누르면 요약으로 돌아간다.
- 보유 종목 탭에서는 오른쪽에 보유 상세(수량, 평균 매입가, 평가, 손절·익절 기준선, 거래 이력, 전량 매도).

**모바일** (375 기준): 헤더 56px + 자산 카드 + 3탭(스윙 추천 / 보유 종목 / 요약).
- 목록은 아코디언, **한 번에 하나만 펼침**. 펼친 상태에서는 화면 아래에 매수 바를 고정(총 결제 예상액 + 주 버튼).
- 요약 탭은 PC 요약 패널을 세로로 쌓은 것(추천 등급 분포 도넛은 길이 때문에 모바일에서 뺌).

**헤더**: PC는 아바타, 앱 이름, 증권사 알약, 검색창, 알림, 새로고침. 모바일은 앱 이름, 증권사 알약, 검색, 새로고침, 내 메뉴.
**내 메뉴**(아바타/사람 버튼): 알림 설정, 로그아웃, 구분선, 계좌 초기화(빨강). 초기화는 헤더에 두지 않는다(새로고침 아이콘과 혼동, 실수 방지).

## 3. 토큰
| 항목 | 값 |
|---|---|
| 바탕 | `#000000` + 모서리 쪽 radial 번짐 3개(파랑 `rgba(70,110,255,.38)`, 보라 `rgba(150,90,255,.30)`, 청록 `rgba(20,190,170,.26)`) |
| 글자 | 본문 `#f5f5f7`, 보조 `#d3d6e2`, 흐린 글자 `#a9aebf`(그보다 어두운 회색 금지) |
| 상승 | 글자 `#ff6a60`, 막대·채움 `#ff453a` (한국식: 상승=빨강) |
| 하락 | 글자 `#5aa9ff`, 막대·채움 `#0a84ff` |
| 긍정·A등급·현금 | `#30d158`(글자 `#4be07a`), S등급 `#ffd60a`, B등급 `#8e8e93` |
| 위험·파괴 | `#ff453a`(버튼), 경고 글자 `#ff6a60` |
| 증권사 알약 | 주황 `#ff9f0a` 계열(배경 14%, 테두리 32%) |
| 주 버튼 | 배경 `#f5f5f7`, 글자 `#0b0d12` |
| 글라스 카드 | 배경 `rgba(255,255,255,.08)`, 테두리 `1px rgba(255,255,255,.20)`, `backdrop-filter: blur(10px)`, 그림자 `0 0 24px rgba(140,170,255,.18), 0 8px 20px rgba(0,0,0,.35)` |
| 카드 안쪽 칸 | `rgba(0,0,0,.35)`(수치 칸), 구분선 `rgba(255,255,255,.10)` |
| 헤더 | 배경 `rgba(21,24,34,.72)`, blur 12px, 아래 테두리 `rgba(255,255,255,.16)` |
| 모바일 하단 매수 바 | 배경 `rgba(18,18,24,.88)`, blur 12px, 위 테두리 `rgba(255,255,255,.16)` |
| 모달 | 배경 `rgba(18,18,24,.88)`, blur 16px, 테두리 `rgba(255,255,255,.16)`, 반경 18px, 뒤 막 `rgba(5,6,10,.6)` + blur 6px |
| 선택된 항목 | 탭: 밝은 면 `#f5f5f7` + 어두운 글자. 목록 행: `rgba(255,255,255,.16)` + 테두리 `rgba(255,255,255,.30)` |
| 반경 | 카드 PC 14px / 모바일 16px, 모달 18px, 버튼 10~12px, 알약 999px |

**글라스 값의 출처**: 모달·하단 바의 불투명도 88%, 테두리 16%, 반경 18px은 Pane 프로젝트(`styles/glass_theme.py`)에서 가져왔다.
**헤더 불투명도 (사용자 결정, 2026-10-26)**: 시안 중 PC 상세 보드와 모바일 보드의 헤더는 `rgba(21,24,34,.72)`, PC 요약·보유·빈 상태·로딩·오류 보드의 헤더는 `rgba(18,18,24,.88)`로 그려져 있다. **구현은 `.72`로 통일**한다. 헤더 글자가 배경에 묻혀 읽기 어려우면 그때 `.88`로 올린다(사용자가 실제 화면을 보고 판단).

## 4. 타이포·크기
- 글꼴: Pretendard, -apple-system, Malgun Gothic 순.
- 최소 글자 크기 **13px**. 목록 행 이름 15px, 가격 16px, 요약 큰 숫자 32~34px(모바일 32).
- 숫자는 항상 `font-variant-numeric: tabular-nums`.
- 터치 영역 **44px 이상**(아이콘 버튼, 탭, 수량 ±, 주 버튼은 48px).
- 보조 글자 대비는 흐린 글자 `#a9aebf` 이상을 유지(검정 위 약 7:1 수준, 측정값은 구현 때 확인).

## 5. 색에만 의존하지 않기
- 등급은 색 + 글자(S/A/B), 증감은 색 + 부호(+/−), 순위는 숫자.
- 상승/하락 색은 상승·하락·손익에만 쓴다. 장식에 쓰지 않는다.

## 6. 상태 화면(PC·모바일 공통 규칙)
- **빈 상태**: 아이콘 + 제목 + 이유 한 줄 + 할 수 있는 행동 버튼(예산 설정, 새로 고침).
- **로딩**: 최종 레이아웃과 같은 모양의 스켈레톤, 1.4초 반복 shimmer. 둥근 스피너 금지.
- **오류**: 목록 영역에 "불러오지 못했어요 + 다시 시도". 시세 실패 시 주문을 막는 이유를 설명(체결가는 서버 실시간 시세로만 정해진다). 마지막으로 확인된 숫자임을 표시.
- **계좌 초기화 확인창**: 지워지는 것(거래 건수, 보유 종목 수, 자산 변화)을 보여주고, 취소와 초기화(빨강)를 같은 크기로 나란히 둔다.

## 7. 동작
- 호버·눌림은 **크기를 바꾸지 않고 밝기·그림자만** 바꾼다.
- 움직임은 적게: 스켈레톤 shimmer, 아코디언 펼침, 모달 등장 정도. `prefers-reduced-motion`이면 끈다.
- `prefers-reduced-transparency`이거나 `backdrop-filter` 미지원이면 글라스 면을 불투명 `#12141c`로 대체한다.
- 카드마다 블러를 쓰면 폰에서 느려질 수 있다. 구현 때 실기기에서 확인하고, 느리면 목록 안쪽 행은 블러 없이 단색으로 둔다.

## 8. 접근성·PWA 정리(첫 구현 PR에 포함)
이전 점검에서 나온 항목 중 이번 개편과 함께 처리한다.
- 아이콘 버튼에 `aria-label`, 이모지·개발용 문구 제거.
- `viewport`의 `user-scalable=no` 제거.
- `manifest.json`·PWA 아이콘 점검.
- 12px 이하 글자를 13px 이상으로.

## 9. 구현 순서(제안, 각 단계는 사용자가 "진행해"라고 한 뒤 시작)
1. 공통 토큰·글라스 클래스·아이콘 세트·13px/44px 규칙·접근성 정리 (화면 구조 변경 없음)
2. 모바일 홈: 헤더 + 자산 카드 + 3탭 + 아코디언 + 하단 매수 바
3. PC 2열 레이아웃(요약/상세 모드)
4. 상태 화면(빈·로딩·오류)과 내 메뉴·초기화 확인창
5. 요약 탭/패널의 차트·도넛 (거래별 손익은 실제 거래 기록에서 계산)

## 10. 열린 결정
1. 시안 원본을 저장소에 넣을지(예: `docs/design/` 아래 HTML) 아니면 캔버스에만 둘지.
2. 매수 전 확인창을 넣을지(지금 시안은 PC 매수 패널·모바일 하단 바에서 바로 매수).
3. 알림 설정 동작(토글인지 설정 화면인지).
4. 초기화 확인을 버튼 두 개로 충분히 볼지, 직접 입력까지 요구할지.
5. 모바일 요약 탭에 추천 등급 분포를 넣을지.
6. 시안의 숫자(보유 종목 카카오 2주, 거래 4건, 승률 50% 등)는 예시값이다. 서버가 실제로 주는 값과 맞는지는 구현 전에 확인한다(특히 초기화 확인창의 요약값).
