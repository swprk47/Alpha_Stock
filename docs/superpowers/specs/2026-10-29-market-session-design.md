# 2단계 — 장 상태 태그·장 시간 안내·장 마감 중 주문 정책 설계

작성일 2026-10-29 · 브랜치 `feat/market-status`(단독 PR) · 시안: 디자인 캔버스 "시세 실패 표시 시안" 아래 두 줄(모바일 Mk1~Mk5, PC Pc1~Pc3)

## 1. 목적과 사용자 결정

시세 정확성이 최우선인 앱이다. 지금은 장이 닫혀 있어도 종가를 "현재가"처럼 보여 주고, 모의 주문이 그 순간 응답받은 가격으로 언제든 체결된다. 사용자가 정한 것:

| 결정 | 내용 |
|---|---|
| 장 상태 표시 | **종목별 태그**: 프리마켓 / 정규장 / 애프터마켓 / 장 마감 (헤더 알약은 두지 않음) |
| 태그 위치 | 모바일 매수 시트 **제목줄**, PC 상세 헤더(추천·검색·보유)의 칩 줄 끝 |
| 태그 클릭 | **"장 시간 안내" 팝업**: NXT / KRX **탭** 둘, 탭마다 시간대를 색으로 나눈 얇은 막대, 현재 시각은 **V자 아이콘** |
| 주문 정책 | 장 마감 중에도 주문은 **허용**하되 확인창에 경고 한 줄 |
| 설정 | 내 메뉴 "장 마감 중 거래"(허용/차단), 사용자별, **서버가 강제**, 기본 허용 |
| 원칙 | 같은 말을 한 화면에 여러 번 하지 않는다(시세 실패 표시에서 받은 지적) |

범위 밖: 시간외 가격(`overPrice`) 표시, 헤더 알약, `strategy.py`, 보유 화면의 오늘 등락률, 휴장일 달력.

## 2. 네이버 응답에서 확인한 값 (2026-10-29 20:38 관측)

| 대상 | `marketStatus` | `marketSessionType` | 비고 |
|---|---|---|---|
| 삼성전자·SK하이닉스 | CLOSE | afterMarket | `closePrice`는 정규장 종가, 시간외 가격은 `overMarketPriceInfo.overPrice` |
| ETF(KODEX 200, TIGER 미국S&P500) | CLOSE | regularMarket | `overMarketPriceInfo` 없음 |
| KOSPI·KOSDAQ 지수 | CLOSE | 없음 | 쓰지 않음 |

- 같은 날 16:50쯤 삼성전자는 `OPEN`(시간외 거래 중), ETF는 `CLOSE`였다 → `marketStatus` 하나로는 "장중"을 판단할 수 없다.
- `marketStatusDetailType`은 `close`(관측). 다른 값은 모른다 → 쓰지 않는다.
- 추천 후보 목록(`marketValue`)은 `marketStatus`와 `overMarketPriceInfo`만 있고 `marketSessionType`이 없다.

**아직 못 본 값(다음 거래일 2026-10-30 아침에 관측해 확인):** 정규장 중의 `OPEN`+`regularMarket`, 프리마켓 시간대의 `marketSessionType` 이름과 `closePrice`(전일 종가인지), 휴장일의 값.

## 3. 상태 모델

서버의 순수 함수 `market_session(marketStatus, marketSessionType)` 하나가 판단한다(`backend/market_data.py`). 반환: `"regular" | "pre" | "after" | "closed" | "unknown"`.

| marketStatus | marketSessionType | 결과 |
|---|---|---|
| OPEN | regularMarket | regular |
| OPEN | afterMarket | after |
| OPEN | preMarket | pre *(이름은 관측 전 가정, 아래 검증 후 확정)* |
| CLOSE | (무엇이든) | closed |
| 그 밖·누락·이상한 값 | | unknown |

- 규칙은 한 곳에만 둔다. 화면은 이 결과(`state`)만 쓰고 시계로 추측하지 않는다(공휴일을 모르므로).
- 모르는 값은 추측하지 않고 `unknown`으로 두며, 화면은 태그를 달지 않는다.
- `nxt_listed: bool` = 시세 응답에 `overMarketPriceInfo`가 있는지(데이터 기반, 추측 아님). 팝업의 NXT 탭은 `nxt_listed`일 때만 보인다. *(ETF에 NXT가 없다는 것은 확인된 사실이 아니라 오늘 응답에 정보가 없었다는 관측이다.)*

응답에 붙는 모양: `market_state: {"state": "after", "nxt_listed": true}`.

## 4. 서버

### 4.1 시세에 상태 붙이기
- `get_realtime_stock_info`가 `market_state`를 돌려준다(위 순수 함수 + `nxt_listed`).
- 노출 위치: `/api/stock/{code}`(`get_stock_detail_with_chart`), `/api/portfolio`의 보유 종목별(이미 종목마다 시세를 받으므로 추가 호출 없음), 추천 항목(아래).
- **추천**: `attach_diagnosis`와 같은 방식으로 `server._compute_bucket`이 종목별 시세로 상태를 이어 붙인다(`strategy.py`는 바꾸지 않는다). 추천 캐시 주기만큼 늦을 수 있어, 경고·강제는 항상 **주문 시점** 서버 값으로 다시 판단한다.
- 검색 결과 행에는 붙이지 않는다(태그는 상세에만).

### 4.2 설정 저장과 API
- 사용자 JSON(`data/users/*.json`)에 `settings: {"allow_closed_trading": true}`를 둔다. 키가 없으면 기본 `true`로 읽는다(마이그레이션 없음). `reset()`은 설정을 건드리지 않는다.
- `GET /api/me` 응답에 `settings`를 넣는다.
- `POST /api/settings`: 요청 스키마 `SetSettingsRequest(_Strict)`, 필드 `allow_closed_trading: bool`만(그 밖은 422). 로그인 필요(401). 사용자 락 안에서 저장(`portfolio.set_setting`).

### 4.3 주문 강제
- `orders.place_buy`·`place_sell`: `fetch_live_quote` 직후 `market_session`을 보고, 상태가 `pre|after|closed`이고 `allow_closed_trading`이 꺼져 있으면 **409**와 메시지 "장 마감 중에는 주문하지 않도록 설정돼 있어요. 내 메뉴에서 바꿀 수 있어요."로 거부한다.
- `regular`는 항상 허용. `unknown`은 **막지 않는다**(연습을 막지 않는 쪽). 설정이 켜져 있으면 모든 상태 허용.
- 매도 미리보기(`/api/sell/preview`)는 읽기 전용이라 막지 않는다.
- 체결가는 지금처럼 서버가 받은 `current_price`(정규장 종가)이고 변경하지 않는다.

## 5. 프론트

모두 `frontend/index.html` 한 파일. 새 순수 함수 구간 `// <market-logic>`(DOM 없음, node 테스트).

### 5.1 태그
- `sessionTag(ms)` → `{label, tone}`: 정규장(초록)·프리마켓(하늘)·애프터마켓(보라)·장 마감(회색), `unknown`이면 태그 없음. 색과 글자를 함께 쓴다.
- 태그는 `<button>`이고 `aria-label="장 시간 안내 열기"`, 누르면 팝업을 연다.
- 위치: 모바일 매수 시트 제목줄("종목 매수" 옆), PC 추천·검색·보유 상세 헤더 칩 줄 끝.

### 5.2 "장 시간 안내" 팝업
- `role="dialog" aria-modal="true"`, 제목 "장 시간 안내". Esc는 맨 위 겹만 닫고, 초점 가둠·복귀는 기존 시트와 같은 규칙. 탭은 `role="tablist"`, 화살표 키로 이동.
- 탭: **NXT**(`nxt_listed`일 때만), **KRX**. 기본 탭은 KRX(정규장 기준, 모의 체결가의 기준).
- 막대: 08:00~20:00 축을 두 탭이 같이 쓴다. 구간 색 + 범례(이름·시각 글자). 쉬는 시간은 어두운 회색.
- 현재 시각: 막대 위 "지금 HH:MM" 글자와 **V자 아이콘**(꺾쇠, 흰색). 양 끝 근처에서는 글자 정렬만 붙인다. 시간표 밖(08:00 이전·20:00 이후·주말)이거나 `state == "closed"`이면 V를 그리지 않고 "지금은 시간표 밖이에요" 한 줄. 시각은 `Asia/Seoul` 기준으로 계산한다.
- 아래 설명: "모의 주문은 정규장 종가로 체결돼요. 공휴일·휴장일에는 열리지 않아요." + "2026.10.29 확인 · 시간은 바뀔 수 있어요."
- 시간표는 상수 하나(`MARKET_HOURS`)에 두고 `asOf` 날짜를 같이 둔다(네이버 응답에는 시간표가 오지 않는다). 값은 6절의 확인된 구간만 넣는다(KRX는 정규장만).

### 5.3 주문 확인창 경고
`buyConfirmCfg`·`sellConfirmCfg`에 경고 한 줄(`warn`)을 추가한다. 정규장이면 없다.

| 상태 | 경고 문구 |
|---|---|
| regular | 없음 |
| pre | "프리마켓이에요. 체결가는 전 거래일 종가로 정해져요." *(관측 전 가정)* |
| after | "애프터마켓이에요. 체결가는 정규장 종가 N원으로 정해져요." |
| closed | "장 마감이에요. 마지막 정규장 종가로 체결돼요." |
| unknown | "장 상태를 확인하지 못했어요. 체결가는 주문 시점 시세로 정해져요." |

경고의 가격은 화면에 불러 둔 값이고 실제 체결은 서버 시세라, 확인창 아래의 기존 문구("체결가는 서버 실시간 시세로…")는 그대로 둔다. 설정이 "차단"이고 정규장이 아니면 확인창을 열지 않고 서버 거절과 같은 안내를 보인다(서버가 최종).

### 5.4 내 메뉴 토글
알림 설정 아래 행 "장 마감 중 거래 · 허용/차단". 누르면 `POST /api/settings`를 부르고 서버 응답대로 바꾼다(낙관적 갱신 없음). `api()`에 409 메시지 처리를 추가한다.

## 6. 시간표 상수와 미결 사항

| 거래소 | 구간 | 출처·상태 |
|---|---|---|
| NXT | 프리마켓 08:00~08:50 / 메인마켓 09:00:30~15:20 / 애프터마켓 15:40~20:00 | **공식 페이지 확인**(nextrade.co.kr 시장 개요). 페이지에 기준일 없음. 쉬는 시간(08:50~09:00, 15:20~15:40)은 시간표 사이 빈 구간에서 도출 |
| KRX | 정규장 09:00~15:30 | 여러 출처가 일치(공식 주식 페이지는 직접 확인 못 함) → **상수에 넣는다** |
| KRX | 장전·장후 시간외, 2026-09 도입된 프리마켓·애프터마켓 | **출처마다 다름**(장전 07:30/08:30~09:00, 장후 15:30/15:40~18:00/20:00). 확정 못 함 → **상수에 넣지 않는다** |

KRX 공식 API(신청·인증·연 1회 갱신 필요)는 쓰지 않는다. 필요한 것은 시간표 숫자 몇 개뿐이고, 시세·상태는 네이버 응답을 쓴다.

**결정(사용자, 2026-10-29): KRX 장전·장후 시각은 추후에 확인하고, 지금은 알려진 값만 쓴다.**
- KRX 탭에는 **정규장 09:00~15:30**만 막대에 그리고, 막대의 나머지 시간은 어두운 회색으로 둔다. 범례 맨 아래에 "그 밖의 시간(장전·장후 시간외, 프리·애프터마켓)은 확인 중이에요" 한 줄을 둔다. 확인되면 `MARKET_HOURS`의 KRX 항목에 구간만 추가한다(코드 구조 변경 없음).
- NXT 탭은 위 공식 값 세 구간을 모두 그린다. 시간표 사이 빈 구간(08:50~09:00, 15:20~15:40)은 "쉬는 시간"으로 표시한다.
- 기준일(`asOf`)은 공식 개정일이 아니라 **값을 확인한 날 2026-10-29**로 적고, 팝업에는 "2026.10.29 확인 · 시간은 바뀔 수 있어요"로 보인다. NXT 페이지에 개정일이 없기 때문이다.

**남은 미결(구현을 막지 않음):**
- **관측 대기(다음 거래일 2026-10-30 아침):** 정규장·프리마켓의 실제 응답 값(2절). 프리마켓 판단 규칙(`OPEN`+`preMarket` → `pre`)과 문구는 지금은 **가정**이다. 가정이 틀려도 그 상태는 `unknown`으로 떨어져 태그가 없고 경고는 "확인하지 못했어요"가 되며 주문은 막히지 않는다(안전한 쪽). 구현 때 테스트에 "가정"으로 표시하고, 관측 뒤 맞춘다.
- **추후:** KRX 장전·장후 시각.

## 7. 오류·예외

- 시세 실패: 지금처럼 주문은 503. 상태는 `unknown`.
- 필드 누락(옛 응답·캐시): `unknown`, 태그 없음, 경고는 "확인하지 못했어요".
- 장 상태가 바뀌는 순간(15:30 직후 등): 화면의 상태는 늦을 수 있으나 서버가 주문 시점 값으로 강제하므로 안전하다.
- 휴장일·주말: 네이버가 `CLOSE`를 주는 한 "장 마감". 달력은 두지 않는다.
- 단기과열 종목 등 특수 규정은 다루지 않는다.

## 8. 테스트 계획 (TDD, 먼저 실패 확인)

- `market_session` 표(위 3절 전 조합 + 누락·쓰레기 값). `nxt_listed`.
- 시세·상세·보유·추천 응답에 `market_state`가 붙는지.
- 설정: 기본 허용, 저장·재로드, 스키마 `extra=forbid`(422), 미로그인 401, reset이 설정을 지우지 않음, 옛 사용자 파일(키 없음).
- 강제: 차단+(pre|after|closed) → 409, 차단+regular → 통과, 차단+unknown → 통과, 허용+모두 통과, 매수·매도 둘 다, 미리보기는 막지 않음.
- 프론트 순수 함수: `sessionTag`, 경고 문구 표, 막대 구간·V 위치 계산(양 끝, 시간표 밖, closed), 탭 대상(`nxt_listed`). 소스 구조: 태그가 4곳에 붙었는지, 팝업의 `role`·`aria`, 메뉴 행, 확인창 `warn`.
- 화면 확인(모바일 375·360, PC 1280): 가짜 상태를 주입해 태그 4종·팝업 두 탭·경고·토글 확인. 실제 정규장·프리마켓은 다음 거래일 아침에 본다.
