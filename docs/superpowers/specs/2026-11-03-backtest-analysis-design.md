# 스윙 추천 규칙 검증 분석 설계

작성일 2026-11-03 · 브랜치 `feat/backtest-analysis`(PR #30 `feat/backtest-design` 끝에서 분기, 설계 문서 먼저, 구현은 승인 뒤)

## 1. 목적과 사용자 결정

2026-11-02 백테스트(PR #30)는 현재 규칙의 거래당 기대 손익이 비용 반영 후 약 0 이하이고, 무작위 대조군과 일관된 차이가 없으며, 약세장에서 손실이 난다는 기준선을 만들었다. 다만 그 결과에는 **신뢰구간이 없고**, 최대 낙폭이 거래 수익률의 단순 누적이라 계좌 낙폭이 아니며, 점수·지표별로 어디에 힘이 있는지 알 수 없다.

이번 단계는 같은 도구 위에 **분석 층**을 얹어 "이 결론이 우연일 확률"까지 말할 수 있게 한다. 우리가 만드는 것은 **예측기가 아니라 검증기**다. 지금 규칙(과 그 구성 요소)이 과거에 통했는지, 통한 부분이 학습 때 보지 않은 기간에서도 통했는지를 확인한다.

| 결정 | 내용 |
|---|---|
| 접근 | 사용자가 "쓸 만한 건 전부 모아서"로 확정. 앞선 합의(접근 A: 요소별 구간 기대값, 학습/검증 분리, 날짜 군집 신뢰구간, 미리 정한 소수 요소)에 PDF·기사에서 가져온 세 가지(단순 보유 대비 계좌 곡선, 부트스트랩 신뢰구간, 추천 3종목 상관)와 거래 재추출 위험 분포를 더한다 |
| 분석 대상 | **본 분석: 앱이 실제로 보는 후보 풀(날짜별 앞 30개)**. **확인용: 같은 필터를 통과한 전체 풀(최대 300)**. 두 결과가 같은 방향인지 나란히 낸다 |
| 입력 | 이미 만든 `backtest/cache/`의 일봉(300종목). **일봉은 다시 받지 않는다**(캐시가 없으면 `backtest.run`을 먼저 실행). 상장 목록은 캐시에 없어서 첫 실행에서 한 번(6쪽) 받아 `backtest/cache/listing.json`에 저장하고 이후 재사용한다. 거래는 일봉에서 다시 시뮬레이션하므로 `trades.csv`에 의존하지 않는다 |
| 코드 범위 | `backtest/analysis/` 새 폴더만. `strategy.py`와 앱 코드는 읽기·import만 한다 |
| 결과물 | 로컬 보고서(`backtest/results/`, 커밋 제외). 규칙 변경은 이 문서의 범위 밖이며 별도 설계와 승인이 필요하다 |

범위 밖: 페어 트레이딩(공매도가 필요하고 우리 롱 스윙과 다른 전략이라 PDF 프로젝트 2는 채택하지 않음), `strategy.py` 변경, 새 전략 설계, 장중 거래량 문제(일봉으로 재현 불가), 화면·서버 API, 실거래 연동, 요소 두 개 조합(상호작용)은 단일 요소가 통과한 뒤에만 다음 단계에서 본다.

## 2. 출발점 (2026-11-02 기준선, 로컬 보고서)

| 항목 | 값 |
|---|---|
| 규모 | 300종목, 2014-08 ~ 2026-11, 예산 10만/20만/50만 x 종가·다음날 시가 진입, 시나리오마다 약 4,600건 |
| 추천 상위 3 | 비용 반영 거래당 -0.01% ~ -0.18%, 손익비 0.89~0.99, 승률 약 41%. 슬리피지 0.3% 시 -0.64% ~ -0.78% |
| 대조군 차이 | +0.06%p ~ -0.05%p, 통계 검정은 하지 않았다 |
| 시장 상태 | KODEX 200이 20일선 위인 날 +0.05%, 아래인 날 -0.30%. 연도별 양수는 13년 중 4~6년 |
| 점수 | 거래의 94%가 70점 이상이라 점수별 비교의 표본이 한쪽에 쏠려 있다 |

이 분석은 위 숫자들에 **구간 추정과 검정**을 붙이고, 기준선이 보지 못한 것(요소별 효과, 계좌 수준 위험)을 채우는 일이다.

## 3. 구성

| 조각 | 하는 일 | 입력 |
|---|---|---|
| `analysis/features.py` | 후보-날짜마다 요소 6개와 앱 점수를 계산(종목당 한 번, 앱의 `calculate_technical_indicators` 재사용) | 일봉 프레임 |
| `analysis/panel.py` | 후보-날짜 패널 구성: 요소값, 순손익(`simulate_trade` 결과), 시장 상태, 학습/검증 구분 | features + simulate |
| `analysis/bootstrap.py` | 날짜 블록 부트스트랩(공용): 연속 5거래일 블록을 복원 추출, 5,000회, 고정 시드 | |
| `analysis/factors.py` | 요소별 추세 검정과 구간표, Holm 보정, 학습/검증 판정 | panel + bootstrap |
| `analysis/selection.py` | "추천 상위 3 - 그날 후보 풀 평균"의 신뢰구간 | panel + bootstrap |
| `analysis/equity.py` | 일봉 기준 계좌 곡선, 단순 보유 비교, 낙폭·샤프 | 거래 + 일봉 |
| `analysis/correlation.py` | 추천 3종목 상관과 동시 손절 비율 | 일봉 + 거래 |
| `analysis/risk.py` | 거래 재추출로 가상 계좌 곡선을 만들어 위험 분포 계산 | equity + bootstrap |
| `analysis/report.py`, `analysis/run.py` | 보고서(`analysis_report.md`, `analysis.json`)와 `python -m backtest.analysis.run` | 위 전부 |

의존 방향은 `features → panel → factors/selection`, `equity → risk`, `correlation`은 독립이다. 순수 함수 위주로 두고 파일·네트워크 접근은 `run.py`에만 둔다. 모든 모듈은 재현을 위해 시드를 인자로 받는다.

## 4. 요소별 예측력 분석

**4.1 단위.** 신호가 난 날의 후보 풀 **전체**(통과 종목만이 아니라 후보 30개 모두). 점수 필터가 이미 거른 뒤의 표본으로는 요소 자체의 힘을 볼 수 없기 때문이다. 확인용으로 필터 통과 전체 풀(최대 300)을 같은 방식으로 돌려 나란히 둔다.

**4.2 결과값.** 기존 `simulate_trade`의 비용 반영 순손익. 기본은 **다음날 시가 진입 + 슬리피지 0.1%**이고, 종가 진입은 확인용이다.

**4.3 요소 6개와 앱 점수 (사전에 고정).** 요소와 구간 경계는 이 문서에서 정하고, **학습 기간 결과를 보기 전에** 바뀌지 않는다. 분위수 경계는 학습 기간 데이터로만 계산해 검증 기간에 그대로 적용한다.

| 요소 | 정의 | 구간 |
|---|---|---|
| 종가의 20일선 이격 | (종가 - MA20) / MA20 | 0 미만 / 0~3% / 3~6% / 6% 초과 |
| 5일선과 20일선 간격 | (MA5 - MA20) / MA20 | 학습 기간 4분위 |
| RSI14 | 앱 `rsi14` | 30 미만 / 30~45 / 45~60 / 60~70 / 70 초과 |
| 거래량 비율 | 당일 거래량 / 5일 평균 | 학습 기간 5분위 |
| 볼린저 위치 | %B = (종가 - `bb_lower`) / (`bb_upper` - `bb_lower`), 앱 `calculate_technical_indicators`의 컬럼 | 0 미만 / 0~0.5 / 0.5~1 / 1 초과 |
| 변동성 | ATR14 / 종가 (앱 지표에 없어 분석 층에서 직접 계산. 참 범위(true range)의 14일 단순평균으로, 앱 RSI와 같은 단순 롤링 방식) | 학습 기간 3분위 |
| (7) 앱 점수 | `analyze_stock_for_swing`의 점수. 앱 함수가 60 미만이면 `None`을 돌려줘 **통과 종목에서만** 점수를 알 수 있으므로, 이 요소만 통과 종목 표본으로 검정한다 | 60~69 / 70~79 / 80 이상 |

구간에 거래가 **200건 미만**이면 이웃 구간과 합치고, 건수는 항상 함께 적는다.

**4.4 검정.** 요소 하나당 "값이 클수록 순손익이 달라지는가"를 **순위상관 기울기 한 번**으로 검정한다(구간별 전수 비교를 하지 않아 비교 횟수를 7로 고정). 7개 검정에 **Holm 보정**을 적용한다. 신뢰구간은 4.6의 블록 부트스트랩으로 구한다.

**4.5 학습/검증.** 학습 2014-08 ~ 2021-12, 검증 2022-01 ~ 2026-11. 요소가 "힘이 있다"는 판정은 **둘 다** 만족해야 한다.
1. 학습 기간에서 Holm 보정 후에도 유의
2. 검증 기간에서 같은 방향이고 95% 구간이 0을 포함하지 않음

하나라도 빠지면 **"근거 부족"**으로 적는다. "효과 없음"이라고 단정하지 않는다(표본이 작아 못 본 것일 수 있다).

**4.5-1 안정성(관계는 깨진다).** PDF 프로젝트 2의 "관계는 깨지므로 주기적으로 다시 검증한다"를 따라, 힘이 있다고 판정된 요소에 대해 **연도별 효과 방향**(양/음)을 표로 낸다. 연도의 3분의 2 이상에서 방향이 같지 않으면 판정에 "불안정" 표시를 붙인다. 학습/검증 한 번 나누기를 대체하지 않고 보강한다.

**4.6 블록 부트스트랩.** 같은 날 종목들은 같이 움직이고 5일 보유라 이웃한 날의 거래가 겹친다. 거래 단위로 뽑으면 신뢰구간이 지나치게 좁아지므로, 신호일을 시간순으로 놓고 **연속 5거래일 블록**을 복원 추출한다(5,000회, 시드 고정, 시드 값은 보고서에 기록). 순위는 전체 표본에서 한 번만 매기고 재추출 동안 고정한다(날짜별 합계로 계산해 속도를 확보). p값은 재추출 분포가 0을 넘나드는 비율의 두 배(백분위 방식)로 구한다. 새 외부 의존성(scipy 등)은 쓰지 않고 numpy·pandas만 쓴다.

**4.7 추천 선택 효과.** "매일 추천 상위 3 평균 순손익 - 그날 후보 풀 평균 순손익"의 평균과 95% 구간을 같은 부트스트랩으로 낸다. 기준선의 대조군 비교를 검정으로 바꾼 것이다.

## 5. 계좌 곡선과 단순 보유 비교

**5.1 곡선 구성.** 거래 기록에는 중간 평가액이 없어서 캐시된 일봉으로 보유일마다 **종가 기준 평가**를 한다.
- 5일 보유가 겹치므로 그날 **보유 중인 모든 포지션에 균등 배분**(매일 재조정)하고, 보유 포지션이 없는 날은 현금(수익 0)으로 둔다. 거래 목록은 `simulate_picks`(같은 종목 중복 보유 제외)의 결과를 그대로 쓴다.
- 진입일·청산일에 수수료·세금·슬리피지를 반영하고, 익절·손절·만료 체결가는 기존 `simulate_trade`와 동일하게 쓴다.
- 일중 변동은 종가로만 본다(장중 낙폭 과소평가는 한계로 명시).

**5.2 비교 대상.**
| 대상 | 이유 |
|---|---|
| KODEX 200 계속 보유 | 기본 비교 |
| KODEX 200을 **같은 날들만** 보유 | 우리는 신호가 난 날에만 투자하므로 투자 기간을 맞춘 공정 비교 |
| 현금 | 아예 안 하는 것보다 나은지 |

KODEX 200(코드 `069500`) 일봉은 기존 `RunConfig.benchmark_code`가 가리키는 데이터를 재사용한다(캐시에 없으면 `backtest.run`이 받아 둔 것을 쓴다).

**5.3 지표.** 연환산 수익률, 최대 낙폭, 샤프(무위험수익률 0 가정, 보고서에 명시), 시장 노출 비율(투자한 날 / 전체). 여기에 **정보비율**(연환산 초과수익 / 연환산 추적오차, KODEX 200 대비)을 더한다. 우리와 각 비교 대상의 **차이**에도 4.6의 부트스트랩 신뢰구간을 붙인다. PDF 프로젝트 3의 세 질문도 보고서에 한 줄씩 답한다: ① **비용이 얼마를 깎았나**(비용 전·후 수익 차이), ② **하루 늦게 진입하면 얼마나 바뀌나**(종가 진입 vs 다음날 시가 진입 차이), ③ **추세장/횡보장에서 어떻게 다른가**(기존 KODEX 200 20일선 상태 구분을 그대로 사용). 이 곡선이 기준선 보고서의 "수백 %p로 나오는 최대 낙폭" 문제를 대체한다.

## 6. 추천 3종목 상관

- 매일 3종목의 최근 60일 일간 수익률 **쌍별 상관 평균**을 구하고, **같은 날 후보 풀에서 무작위로 3개 뽑은 경우**(20회 반복)와 비교한다. 앱이 비슷한 종목을 몰아 추천하는지 본다.
- **3종목이 모두 손절된 날의 비율**을, 서로 독립이라고 가정한 기대값(종목별 손절 확률의 곱)과 비교한다. 크게 높으면 3개 분산이 실제로는 분산이 아니라는 뜻이다.
- **상관 민감도**(PDF 프로젝트 1의 "가장 가치 있는 출력"): 날들을 3종목 평균 상관의 3분위(낮음/중간/높음)로 나누고, 분위별로 그날 3종목 평균 손익의 흩어짐(표준편차)과 하위 5% 평균을 비교한다. 상관이 높은 날 위험이 비선형으로 커지는지(분산이 실패하는지)를 과거 데이터로 본다. 정규분포 시뮬레이션에 상관을 억지로 올리는 방식은 쓰지 않는다.
- 추천이 3개 미만인 날은 제외하고 그 일수를 적는다.

## 7. 거래 재추출 위험 분포

정규분포로 난수를 만들지 않고(드리프트·꼬리를 가정하게 되어 갭하락 손절 위험이 사라진다), **실제 일별 계좌 수익률을 블록 부트스트랩으로 이어 붙여** 가상의 계좌 곡선을 만든다.

- 기본 길이 252거래일, 5,000경로. 민감도로 **21일(1개월, PDF 기준)**, 63일(3개월), 756일(3년)도 낸다.
- 지표: 기간 후 이익 확률, 수익률 하위 5%, 하위 5% 평균(CVaR), 최대 낙폭의 중앙값과 95퍼센타일, 낙폭 20% 이상 겪을 확률.
- **시장 상태별** 버전(KODEX 200이 20일선 위/아래인 날만 모은 풀)도 낸다. 약세장 손실을 평균에 묻지 않기 위해서다.
- **보정 점검(Kupiec 방식 VaR 백테스트, Learn-Quant 저장소에서 가져옴):** 위험 분포를 **학습 기간(2014~2021)만으로** 만들고, 검증 기간(2022~2026)의 실제 21일 구간 수익률 중 **분포의 하위 5%보다 나쁜 구간이 몇 %인지** 센다. 기대값은 약 5%이고, 크게 벗어나면(비율 검정, 중첩 구간이라 블록 부트스트랩 구간으로 판정) 이 위험 분포가 위험을 과소·과대평가한다는 뜻이라 보고서에 그대로 적는다. 우리가 만든 "예측 범위"가 실제로 맞았는지 확인하는 장치다.
- 첫머리에 "미래를 맞히는 것이 아니라 과거 12년 분포가 이어진다고 가정한 범위"라고 적는다.

## 8. 보고서와 한계

보고서는 결론보다 **한계를 먼저** 적는다. 반드시 들어갈 한계:
- 후보 풀이 오늘의 시총 목록이라 **생존 편향**(결과가 좋게 나오는 쪽)
- 일봉이라 장중 신호·거래량 문제, 장중 낙폭을 재현하지 못함
- 같은 날 익절·손절이 모두 닿으면 손절로 가정
- 요소는 6개와 점수로 한정했고 다른 요소는 보지 않았음
- 검증 기간은 약 5년이라 표본이 제한적임
- 분할 오탐 가능성이 있는 종목 제외 일수(기준선에서 확인 못 한 항목)

결과 표현 규칙: "유의"는 4.5의 두 조건을 모두 통과한 경우에만, 나머지는 "근거 부족"으로 쓴다. 수치에는 항상 표본 수와 95% 구간을 붙인다.

## 9. 테스트 방침

- 순수 함수는 작은 합성 데이터로 단위 테스트(`tests/test_bt_analysis_*.py`): 블록 부트스트랩의 시드 재현성·블록 경계, 구간 병합 규칙(200건 미만), 학습 기간 분위수 경계가 검증 기간에 그대로 적용되는지, Holm 보정 값, 판정 규칙(학습 통과·검증 실패 → 근거 부족), 계좌 곡선의 비용 반영과 현금 구간, 단순 보유 노출 맞춤, 3종목 동시 손절 기대값, 추천 3개 미만인 날 제외.
- 알려진 답이 있는 합성 문제로 검증: 요소와 손익이 **무관**하게 만든 데이터에서 유의 판정이 Holm 보정 후 거의 안 나오는지(오탐률), **관계를 심은** 데이터에서는 학습·검증 모두 통과하는지.
- 추가 항목 테스트: 연도별 방향 일치 판정(3분의 2 기준), 정보비율 계산, 상관 3분위 분할, 보정 점검의 초과 비율 계산(알려진 분포에서 약 5%가 나오는지)과 학습 기간 분포를 검증 기간에 적용하는 방향.
- 일봉 재사용 검증: 분석이 쓰는 `simulate_trade` 결과가 `trades.csv`와 같은 입력에서 같은 값을 내는지.
- 전체 실행은 사용자 환경 로컬 캐시로 한 번 돌려 보고서를 만들고, 수치는 로컬에만 둔다.
- 기존 테스트(1214개)는 그대로 통과해야 한다. 앱 코드 변경이 없으므로 프론트 문법검사는 해당 없음.

## 10. 열린 항목 (구현 계획에서 정할 것)

- 상장 목록은 오늘의 시총 순서라 기준선 실행(2026-11-02) 때와 달라졌을 수 있다. 숫자가 기준선과 조금 다를 수 있으니 보고서에 기준선 대비 차이를 적는다.
- 블록 길이 5는 보유 기간과 맞춘 값이다. 민감도로 3·10도 돌릴지는 계획에서 정한다.
- 전체 풀(최대 300) 확인 분석의 계산량은 아직 측정하지 않았다(확인 못 함). 계획 단계에서 실측 후 병렬 처리 여부를 정한다.
- 후보 풀에서 요소를 계산할 때 거래정지·분할 제외 규칙은 PR #30의 `select_pool` 규칙을 그대로 따른다.
- 이 분석에서 "근거 있는 요소"가 나오더라도 `strategy.py` 변경은 별도 설계·승인 뒤에만 한다.
